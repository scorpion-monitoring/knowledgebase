## Definition

A service registry is a maintained record of services and their descriptive metadata, kept so that services can be discovered, compared and reported on.

## Explanation

A registry holds one entry per <Term id="service" />: name, description, provider, category, contact and <Term id="lifecycle-stage" />. It can cover the services of one organisation or of many.

The term has several uses.

- In research infrastructures, a registry is an inventory of services used for discovery and reporting. It can include services that are not yet live.
- In software architecture, a registry lists the network addresses of running software components. The UDDI specification is an example of such a registry for web services.
- In the European Open Science Cloud documents, the live catalogue feeds a registry, which shows that the two terms are related but not identical.

The KB uses the first meaning. The software meaning is not used.

A <Term id="service-catalogue" /> is built for users. A registry is built for the organisation and for tools. Many organisations use one list for both purposes, which is why the terms are often confused.

## Example

An infrastructure keeps one registry of all services of its member institutes. The registry stores each service's provider, category and stage. Management uses it to count live services per provider and to find services without a named contact.

## Not to be confused with

- A <Term id="service-catalogue" />, which lists live services for users.
- A software service registry, which holds the network locations of software components.
- A registry of organisations or people. It records different kinds of things.
